# Fleet incentive and knowledge graph MVP

Historical increment note: default startup now opens the authenticated portal. Use WORKSPACES_AI_MVP.md for current instructions or `--legacy-demo` to reproduce this earlier lab UI.

Implemented November 4, 2026. This extends the course relational prototype with a runnable acceptance slice. The 3MT organizations, VIN-shaped placeholders, fleet assignments and commercial policy are fictional test fixtures, not real business records.

## What now works

1. Prepare Cedar Logistics with 12 pre-existing Northstar fleet vehicles, a new Maple Motors sale, Harbour Service activity and Island Rentals replacement vehicle.
2. Select a JSON RuleVersion at Sale.CompletedAt. Only the bounded `fleet_journey_v1` operator is accepted; no arbitrary expressions are executed.
3. Check six documented conditions: completed/available sale; active program; provider enrollment; sale authorization/capability; historical same-manufacturer fleet threshold; and verified service/replacement evidence with valid capabilities, direct account links and time windows.
4. Calculate 15,000 CAD minor units automatically and atomically create the EventEvaluation, evidence rows, EventAward and cash component. The amount is not preloaded as a synthetic award.
5. Repeated and concurrent requests reuse the original entitlement. Rejected inputs can be corrected and reevaluated through a new immutable run. After issuance, changed inputs flag review; they do not silently rewrite or pay another award.
6. Export the accepted decision snapshot to RDF Turtle or JSON-LD, validate it with SHACL, and execute SPARQL competency queries.
7. Ask bounded questions about the award, failed checks, fleet count and service/rental path. The local assistant queries the RDF and returns source run/rule/snapshot references.

The assistant is deterministic graph retrieval, not an LLM integration. Model-generated language, broad conversational understanding, policy-document retrieval and forecasting remain future work.

## Run in zsh

From the extracted project directory:

```zsh
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-knowledge.txt
./quickstart.sh
```

Open http://127.0.0.1:8000 . Scroll to **Fleet incentive lab**, click **1. Prepare fictional journey**, then **2. Evaluate incentive**. The result should be Qualified, CAD 150.00 for Maple Motors, fleet count 12, six PASS checks. Use the graph download links or ask why the award was granted. Repeat evaluation to verify replay rather than another award.

The base app and automatic evaluator use only the Python standard library. RDF/SHACL/query features require the optional dependencies above. If your macOS Python is managed externally, the virtual environment avoids modifying the system installation.

CLI equivalent on a fresh database:

```zsh
python3 scripts/fleet_demo.py --db data/my-fleet-demo.db --export-dir doc/my-fleet-output
```

It prints the actual calculated decision and exports evaluation.json, fleet-journey.ttl, fleet-journey.jsonld, shacl-validation.txt and graph-answer.json. Re-running against the same database is idempotent.

The new migration is `src/dal/models/relational/sql/09_fleet_engine.sql`:

| Relation | Keys and purpose |
|---|---|
| SchemaMigration | Id autogenerated PK; Version UNIQUE NOT NULL; AppliedAt NOT NULL |
| Fleet | Id PK; ParentCompanyId FK; OwnerAccountId -> CustomerAccount; unique (ParentCompanyId,FleetReference); mandatory name/reference |
| FleetVehicleAssignment | Id PK; FleetId/VehicleId FKs; unique (FleetId,VehicleId,ValidFrom); UTC half-open membership intervals and evidence reference; overlapping assignments for one vehicle rejected |
| IncentiveRun | Id PK; parent company/activity/rule/version FKs; unique (VehicleActivityId,RuleVersionId,InputHash); immutable JSON input/decision snapshot; Qualified requires evaluation/award references, Rejected has neither |

There are now **38 application relations** including SchemaMigration: the baseline 34 plus these four additions. Startup applies the additive migration to an existing database; it never removes or resets baseline data. The original `dictionary.json` and generic CRUD sidebar intentionally cover the 34 baseline relations. The fleet lab manages the extension through its controlled workflow. General-purpose fleet CRUD is not yet implemented.

The report in `doc/report/` describes the earlier 34-relation course baseline. It has not been revised to claim these new features or list the four extensions, so it is not a complete submission report for this expanded MVP. ## Financial and correction semantics

The evaluator uses integer minor units for its reward configuration (15000 = CAD 150.00). It bridges to the baseline NUMERIC cash component only after calculation. Full accounting/settlement still needs a fixed-point/minor-unit ledger.

Finalized engine-issued amounts and awards are immutable. A later revoked identity or changed fleet history sets `review_required` on a reevaluation while preserving the original snapshot/award. This lab does not automatically settle money, cancel an issued award or generate a financial reversal. Those require the planned adjustment/review workflow.

Rule qualification is pinned to the sale completion date. Authorization/program/enrollment intervals are date-granular, while fleet/service/rental timestamps are UTC. Fleet count is taken immediately before sale, excluding the newly sold vehicle. Only explicit direct verified account assertions are accepted; transitive matches are not inferred.

## Graph behavior

The demo vocabulary uses a reserved example.org namespace with opaque company/record paths. It is an RDF projection of immutable run evidence, not a public operational endpoint. The ontology and SHACL shapes are in `src/dal/models/semantic/`, together with four SPARQL competency queries. RDF serialization/validation is on demand; a continuously synchronized triple store and transactional outbox are not yet implemented.

SHACL checks the demo's required activity links, provider/vehicle types, evaluation fields and check results, award beneficiary/amount/currency, and qualified-evaluation consistency. It supplements the deterministic evaluator; passing SHACL is not a claim that an arbitrary commercial policy or real customer identity has been verified.

No personal or real customer data is sent to an AI provider. There is no external model API call, login system or production multi-tenant security in this local single-user server. The demo API fixes its own company context and checks run lookups within that context; this is scoped retrieval, not authenticated tenant isolation.
